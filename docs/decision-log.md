## 2026-03-23 - 前端架构技术选型

### 背景

XNexus 后端 MVP 已完成（Go API 服务器），需要构建前端管理界面。PRODUCT_PLAN.md 原计划使用 shadcn/ui，但用户指令要求评估更可持续的架构方案。

### 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 方案 A | React SPA + shadcn/ui | 简单快速，与 PRODUCT_PLAN 一致 | 不支持模块独立部署 |
| 方案 B | Next.js + SSR | 首屏性能好，SEO 友好 | 架构复杂，需 Node.js 服务 |
| 方案 C | Vite + Module Federation | 支持插件化，可独立部署 | 初期复杂度略高 |

### 决策

**选择方案 C: Vite + Module Federation 微前端架构**

### 理由

1. **符合长期规划**: PRODUCT_PLAN.md 明确提到"前端插件机制"和"插件化视图"需求
2. **独立部署能力**: 各业务域可独立开发、测试、部署，支持灰度发布
3. **团队扩展性**: 未来多团队协作时，各团队可负责独立 MFE
4. **技术现代化**: 使用 Vite 6 + React 19 + TypeScript 5 最新版本
5. **向后兼容**: 保留升级到其他方案的能力

### 权衡

- **初期复杂度**: 相比 SPA 需要额外配置 Federation 插件
- **学习曲线**: 团队需理解微前端概念和 Module Federation 机制
- **调试难度**: 多应用联调比单应用复杂

### 影响

- 需要创建多个前端项目 (host + mfe-*)
- 需要统一共享依赖版本管理
- 需要设计 Host ↔ MFE 通信机制
- 构建脚本需要协调多项目

### 采纳的技术栈

| 层级 | 技术 | 版本 |
|------|------|------|
| 微前端 | @originjs/vite-plugin-federation | ^2.0.0 |
| 构建 | Vite | ^6.x |
| 框架 | React | ^19.x |
| UI | shadcn/ui | latest |
| 样式 | TailwindCSS | ^4.x |

## 2026-03-23 - 微前端拆分策略

### 背景

确定使用微前端架构后，需要决定模块拆分粒度。

### 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 按页面拆分 | 每个页面一个 MFE | 粒度最细 | 过多 MFE 增加维护成本 |
| 按业务域拆分 | 仓库域/任务域/设置域 | 边界清晰，适度聚合 | 需要明确定义域边界 |
| 混合模式 | 核心页面 MFE + 通用组件共享 | 灵活 | 复杂度最高 |

### 决策

**选择按业务域拆分**

### 理由

1. **符合业务逻辑**: 仓库管理、任务调度、系统设置是天然的业务边界
2. **适度聚合**: 避免过细拆分导致的碎片化
3. **便于扩展**: 每个域内可自由添加页面和组件
4. **职责清晰**: 每个 MFE 有明确的业务职责

### 模块定义

| 模块 | 业务域 | 包含功能 |
|------|--------|----------|
| Repo MFE | 仓库管理 | 仓库 CRUD、制品浏览/上传/下载 |
| Task MFE | 任务管理 | 任务列表、触发、执行历史 |
| Setting MFE | 系统设置 | 用户管理、权限配置、系统设置 |

### 影响

- 需要定义清晰的域边界文档
- 跨域功能需要 Host 协调
- 共享组件下沉到 Host

## 2026-03-23 - Host 应用职责定位

### 背景

需要确定 Host 应用应该承担多少功能。

### 候选方案

| 方案 | 描述 | 优点 | 缺点 |
|------|------|------|------|
| 最小化 Host | 只负责认证/导航/MFE 加载 | Host 轻量，职责单一 | MFE 需要重复实现通用功能 |
| 增强 Host | 包含通用组件库 + 状态管理 + 工具 | 避免重复，统一规范 | Host 变重，可能过度抽象 |

### 决策

**选择增强 Host**

### 理由

1. **统一规范**: 所有 MFE 使用相同的组件和工具函数
2. **避免重复**: 通用逻辑只需实现一次
3. **一致性**: 用户体验和代码风格统一
4. **便于升级**: 组件升级只需在 Host 修改

### Host 职责

- 全局认证 (Auth Context + Token 管理)
- 主导航 (Sidebar + Header + Breadcrumb)
- 主题配置 (Color/Motion/Density)
- 通用组件库 (Button/Table/Form/Modal/Toast)
- 状态管理 (QueryClient + 共享 Stores)
- API 服务封装 (Axios 实例 + 拦截器)
- MFE 加载器 (Module Federation Runtime)

### 影响

- Host 代码量增加
- 需要文档化共享组件 API
- MFE 需遵循 Host 的接口约定

## 2026-03-23 - 技术版本选择

### 背景

前端技术更新快速，需要确定使用哪些版本。

### 决策

**全部使用最新稳定版本 (2026 Q1)**

### 版本清单

| 技术 | 版本 | 说明 |
|------|------|------|
| Vite | ^6.x | 最新构建工具 |
| React | ^19.x | 最新框架版本 |
| TypeScript | ^5.x | 最新语言版本 |
| React Router | ^7.x | 最新路由库 |
| TanStack Query | ^5.x | 最新服务端状态管理 |
| Zustand | ^5.x | 最新本地状态管理 |
| TailwindCSS | ^4.x | 最新 CSS 框架 |
| shadcn/ui | latest | 最新组件库 |

### 理由

1. **长期支持**: 新版本有更长的维护周期
2. **性能优化**: 新版本通常有性能改进
3. **开发体验**: 新特性提升开发效率
4. **避免技术债**: 避免短期内再次升级

### 风险与缓解

- **风险**: 新版本可能存在未知 Bug
- **缓解**: 锁定小版本范围，测试充分后再升级
